# Fitness Mobile

### 让训练中的每一次调整，都有据可依。

**架好手机，戴上耳机，把注意力留给训练。**

Fitness Mobile 正在打造一款手机端视觉健身陪练：通过摄像头观察动作，在有足够证据时指出具体部位的问题，用简短语音帮助你及时调整，并在训练后留下可以回看的记录。

我们希望把私教陪练中“观察—提醒—调整”的体验，带到更多人的日常训练里。

**Android 原生 · 端侧分析 · 局部动作反馈 · 可追溯证据**

> 当前为工程实验项目。已建立相机分析、实验提醒、本地视频回放与证据导出链路；已归档的验证基线为 [Android 0.3](docs/validation-v0.3.md)。当前开发代码新增了 32 个动作的离线知识库。真人纠错准确率、真机持续性能与耳机延迟仍待验收。

## 练得认真，也需要及时反馈

独自训练时，你可能记得动作要领，却很难在发力过程中看清自己的姿态：弯举时上臂是否开始摆动？推胸时躯干是否改变了支撑位置？这一组后半程是否还保持着动作控制？

Fitness Mobile 关注这些具体、局部、可以调整的细节。一次动作可以大体完成得很好，同时在某个阶段出现需要提醒的问题。产品围绕“哪里发生了变化、依据是什么、接下来怎么调整”组织反馈，让每条提醒都能回到对应的画面和时间点。

例如，我们希望用户听到这样的短句：

> “先稳住上臂，再完成这次弯举。”

这是一种反馈表达示意；实际是否提醒，取决于所选动作、拍摄条件、关键点可见性和已启用的规则。

## 从架好手机，到看懂这一组

产品围绕三个时刻展开：

| 时刻 | 用户体验 | 产品关注点 |
| --- | --- | --- |
| 训练前 | 选择动作与变式，了解要点，固定手机并确认入镜范围 | 让系统有条件看清需要观察的部位 |
| 训练中 | 专注完成动作，通过简短语音获得提示 | 提醒有证据、有时效，控制重复与打断 |
| 训练后 | 回看相关时间点，查看观测与备注 | 帮助用户理解问题，也让开发者检查判断依据 |

当前可以从两条入口体验：**打开相机进行深蹲或站姿弯举实验训练**，或**导入已有视频进行回放分析**。完整个人档案、多组训练会话与更丰富的组后报告按开发计划逐步完善。

## 我们如何让反馈值得信任

**具体到部位。** 反馈针对上臂、躯干等局部变化。没有收到提醒，不代表所有部位都已检查通过；产品不输出整次动作“标准／错误”的二分类结论。

**看清楚，再评价。** 缺失的关键点保留为缺失。看不清、观测中断或拍摄条件不适配时，相关评价暂停或重置，不跨缺口补出动作次数。

**提醒可以追溯。** 提醒候选携带规则版本、证据时间段和失效时间。实时规则只使用当前与历史观测；过期反馈不会排队到下一次动作才播报。

**分析留在手机。** 核心推理与动作规则在端侧运行，当前应用不申请网络权限，默认不保存相机原视频。导入素材在本机处理，用户可以主动导出分析记录。

**适配通用器械场景。** 通用器械推胸依据动作要点与可观察条件展开，无需填写品牌、型号或铭牌。平推、上斜推举、肩推等变式仍需区分。

## 当前能力

| 能力 | 已实现范围 | 当前边界 |
| --- | --- | --- |
| 相机姿态观测 | 端侧人体关键点、同帧骨骼与二维角度显示 | 遮挡、镜像、多人和机位变化仍会影响观测 |
| 实验计数与提醒 | 深蹲／站姿弯举候选计数；弯举上臂与躯干变化提醒；相机训练中的自设深蹲幅度目标 | 工程阈值尚待真人数据校准 |
| 语音与本地记录 | 提醒去重、冷却、过期处理，以及本地训练组记录和 JSON 导出 | 真实耳机延迟与复杂音频场景待验证 |
| 视频回放分析 | 导入本地视频，查看抽样画面、骨骼、角度、时间点与人工备注 | 当前限两分钟内；解码格式取决于设备；回放不播报历史提醒 |
| 通用器械推胸复核 | 技术要点逐项复核；固定机位下的躯干相对参考变化候选 | 当前通过回放入口使用，尚未接入相机训练菜单 |
| 动作知识库（开发中） | 32 个动作、六类训练部位、分类搜索、技术摘要、复核项目、拍摄条件和来源 | 知识覆盖范围大于自动检测范围 |

已归档验证包括构建、核心回归、模拟器集成测试，以及用户提供视频的完整回放链路。详见 [0.3 验证记录](docs/validation-v0.3.md)。这些结果验证了工程链路，尚不能作为真人纠错精度或真机实时性能的结论。

## 动作知识库

常见动作的知识应当预先准备好。新视频进入系统后，根据用户选择的动作与变式，调用对应的技术要点和复核项目，再由已实现的检测规则分析可观察的问题。

当前开发代码中的 [版本化动作库](protocols/exercise-library.v1.json) 包含：

| 分类 | 数量 | 动作举例 |
| --- | ---: | --- |
| 胸 | 6 | 通用器械推胸、杠铃／哑铃卧推、俯卧撑、绳索夹胸 |
| 背 | 5 | 引体向上、高位下拉、器械划船、杠铃划船、支撑式单臂划船 |
| 肩 | 5 | 器械肩推、站姿杠铃肩推、侧平举、前平举、面拉 |
| 腿臀 | 9 | 徒手／负重深蹲、分腿蹲、硬拉、腿举、腿弯举、臀桥 |
| 手臂 | 4 | 杠铃弯举、锤式弯举、仰卧臂屈伸、窄握卧推 |
| 核心 | 3 | 平板支撑、侧平板支撑、死虫式 |

每个条目保留适用变式、技术摘要、局部复核项目与来源链接；复核项目说明需要什么视角、能观察什么、哪些结论目前无法得出。技术摘要参考 NASM、ACE 的对应动作资料，拍摄条件与复核设计由本项目维护，尚待教练审定。

**载入知识与启用检测分别管理。** 增加一个动作条目不会自动开启纠错。当前库中只有通用器械推胸、徒手深蹲和站姿杠铃弯举明确映射到已有实验模式，其余动作提供观测与人工复核。示范姿势中的角度也不会直接变成适用于所有人的合格线。

## 体验与构建

项目采用原生 Android 路线，支持 Android 8.0（API 26）及以上，构建包含 `arm64-v8a` 与 `x86_64`。当前提供 Debug 工程试用，正式 Release 发布尚未完成。

准备 JDK 21、Android SDK Platform 35 和 Build Tools 35.0.0，配置 `JAVA_HOME` 与 Android SDK 路径。在仓库根目录运行：

```powershell
./scripts/fetch-model.ps1
./android/gradlew.bat -p android :app:assembleDebug :app:lintDebug :motion-core:regressionTest
```

安装构建产物：

```powershell
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

首次构建需要下载依赖和模型，模型会校验指纹并打包进 APK；手机分析无需联网下载模型。中文语音需要设备具备可用的离线 TTS 语音资源。完整环境配置、跨平台命令及设备测试方式见 [Android 开发入口](android/README.md)。

首次体验可先导入一段短视频，检查画面、骨架与角度是否对应，再尝试固定侧面机位下的相机训练。二维角度是图像投影估计，不能直接等同于真实三维关节角度、受力或医学判断。

## 技术实现

Kotlin 与 Jetpack Compose 构建界面，CameraX 负责相机采集，MediaPipe Pose Landmarker 提供端侧姿态观测，独立 Java 核心处理动作状态与反馈规则。

```text
相机画面 / 本地视频
        ↓
共享姿态引擎 → 关键点、二维角度、可见性
        ↓
所选动作与适用条件 → 因果状态机 → 局部问题候选
        ↓
证据、优先级、去重、冷却、过期检查
        ↓
实时训练语音 / 回放复核与本地记录
```

相机与回放共享姿态和规则实现，分别使用实时到达约束与原始视频时间。动作知识以版本化 JSON 维护，执行规则在代码中显式注册。手机运行不依赖 Python、Conda、桌面 CUDA 或父项目目录。

| 目录 | 内容 |
| --- | --- |
| [`android/`](android/) | 原生应用、端侧姿态适配、回放界面和设备集成测试 |
| [`core/`](core/) | 独立动作核心、几何计算、状态机与反馈调度 |
| [`protocols/`](protocols/) | 动作协议、技术参考与离线动作知识库 |
| [`docs/`](docs/) | 架构、开发计划、使用说明与验证记录 |
| [`scripts/`](scripts/) | 模型获取等开发辅助脚本 |
| [`provenance/`](provenance/) / [`licenses/`](licenses/) | 来源追溯、模型与组件许可记录 |

## 接下来，让陪练走进真实训练

下一阶段优先解决真实场景中的观察可靠性：主体跟踪、器械遮挡、镜面与背景人员干扰，以及拍摄机位变化。在此基础上，逐步为更多局部问题接入检测与语音提醒。

每项新能力都需要与教练共同定义适用条件，通过独立标注评估误提醒、漏提醒和反馈延迟，再在真机上验证持续运行、发热、耗电与耳机体验。我们希望衡量的最终价值，是用户能否听懂提示、及时调整，并愿意在下一次训练中继续使用。

欢迎开发者、教练与测试者围绕可复现的问题参与验证：提供动作及变式、拍摄条件、问题时间点、预期提示与设备信息。涉及真人素材时，应先获得授权并确认分享范围。

## 项目来源与许可

Fitness Mobile 从 Good-Badminton / BBA 的健身研究成果中提取可复用的动作语义、几何逻辑与测试数据，作为独立手机产品维护。羽毛球项目与原有离线研究代码保持独立，移动端拥有自己的构建、依赖、模型校验和验证记录。

继承部分保留 Apache-2.0 许可与修改声明；模型和第三方组件分别维护来源及授权依据。本项目新增独立内容尚未指定分发许可，详见 [来源与许可声明](THIRD_PARTY_NOTICES.md)。
