# 本地视频回放分析

Android 0.3 首页点击“导入视频 · 回放分析”，选择器械推胸、其他动作观察、深蹲或站姿弯举。推胸默认使用通用技术要点复核，不需要器械品牌；深蹲/弯举需要确认素材确实是该动作的固定侧面视角。

## 输入和处理

- 系统文件选择器授权读取单个视频，不需要新增存储权限；手机本地运行，无网络推理。
- 当前限制两分钟内、时长可读取且不超过 4K 的视频；具体格式依赖设备解码器。
- MediaExtractor + MediaCodec 顺序解码，以实际输出 presentation timestamp 分析。相邻抽样至少间隔 100 ms，不承诺正好 10 fps；不使用关键帧近邻抽取，不将未来帧贴回过去时间。
- 解码 YUV 转 JPEG95/RGB，按旋转信息校正，最长边缩至 640；应用相机和视频共用 `PoseEngine`、模型阈值、几何映射、追踪及可见性门槛。视频像素转换有损且与相机输入分布不同，回放不能等同于真机相机测量。
- 视频时钟与手机 uptime 分离。离线不套用实时到达过期门槛，否则慢速处理会把历史文件全拒绝；保留观测间隙、顺序与追踪重置。推理耗时只是本次运行诊断，不能作为手机实时延迟。

## 回放与证据

分析完成后可拖动时间轴、播放抽样画面、查看同帧骨骼和角度，以及可见性/规则拒绝原因。播放为分析帧回放，无原视频声音。深蹲/弯举的反馈调度使用视频时间，标为 `offline_simulation_no_audio`，不播放过期语音，也不推断真实 TTS 排队与耳机到达时间。

JSON 保存输入 SHA-256、字节数、模型身份、规则版本、抽样策略、逐帧时间/角度/有效关键点/拒绝原因/准备参考/候选/模拟投递。关节坐标归一化到展示图像，未通过置信度门槛的点为空。报告的肘角可计算帧数可能包含未通过整帧评价门槛的帧，不能作为正确率。

器械推胸按 [技术要点](machine-chest-press-guidance.md) 输出局部发现：固定机位下的躯干变化候选已接入，其余检查项保留待复核原因。腿部缺失不阻断可见肩/肘/腕/髋的局部检查。未确认机位固定时停止躯干变化提醒，避免把相机移动当作身体变化；仍可查看角度。其他未支持动作只输出观测。结果使用 `assessmentScope=local_issues_only`，不生成整次动作二分类。人工备注关联视频时间和检查项，可随 JSON 导出。

临时分析图像位于 app cache 下独立目录，离开回放页清理；取消/失败清理本次部分结果。原文件不改动，回放不写入训练历史。旋转重建或进程结束不保证保留分析；重要结果先导出。系统杀进程可能留下缓存，由系统回收；本版无自动恢复。

## 开发验证

普通 `connectedDebugAndroidTest` 运行回归，不打包私人素材；素材用例无参数时跳过。可在已安装 Debug 应用和测试 APK 的设备上，将素材放入应用可读取的本地路径，再执行：

```powershell
adb shell am instrument -w -r -e replayVideo /data/user/0/fitness.mobile/files/replay-input.mp4 fitness.mobile.test/androidx.test.runner.AndroidJUnitRunner
```

素材用例复用正式解码与分析函数，结果写入应用 files/replay-evidence-*。它验证完整本地视频链路及证据契约，不验证人体角度真值。当前素材实测见 [0.3 验证](validation-v0.3.md)。
