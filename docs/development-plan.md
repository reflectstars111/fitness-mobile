# 手机实时健身陪练开发计划

状态：独立项目准备阶段；已提取纯 Java 几何/研究协议核心、版本化动作目录和合成参考夹具，配置独立测试与 CI。详见 [提取记录](extraction.md)。以下完整产品里程碑仍待执行，不是已交付能力。

## M1 · 真机运行基础

- [ ] 确定 Android 测试设备和支持范围；核对官方示例及许可证。
- [ ] 创建正式 Android 工程，锁定 JDK、Gradle、SDK、依赖及模型身份。
- [ ] 接通摄像头、旋转镜像处理、端侧姿态和骨骼显示。
- [ ] 接通耳机语音、音乐音频焦点、权限及前后台生命周期。
- [ ] 测量持续运行的延迟分布、掉帧、耗电、内存和发热，保留设备与配置记录。

验收：干净环境可构建；真机连续训练测试无崩溃；处理不过来时丢弃过期帧，不累积延迟；不依赖桌面 Python 或联网推理。

## M2 · 可回放的实时动作核心

- [ ] 定义版本化关键点、时间戳、动作协议和结果事件。
- [ ] 从深蹲和站姿弯举开始迁移；四类离线动作不自动等于四类已验收实时能力。
- [ ] 增加机位不适配、多人干扰、关键点缺失及追踪重置。
- [ ] 建立逐帧回放、与离线参考对照和固定预期结果。
- [ ] 测试不完整动作、重复帧、乱序时间戳、断流和恢复；禁止使用未来帧。

验收：同一输入回放结果确定；低质量不补计；每个候选可追溯到证据区间与规则版本。

## M3 · 有节制的实时语音

- [ ] 与教练共同定义每个动作最少且有价值的提醒及适用条件。
- [ ] 区分机位提醒、动作提醒、报数、节奏和组间总结。
- [ ] 实现持续证据门槛、优先级、去重、冷却、过期丢弃及关闭提醒。
- [ ] 使用固定短句与端侧语音；大模型不参与逐帧纠错决策。
- [ ] 记录提醒证据、触发时间和实际播报时间，不默认保存原视频。

验收：同一问题不会反复刷屏或播报；失去观察资格后不继续评价；过期信息不会在下一次动作中才播放。

## M4 · 完整训练流程与真人验收

- [ ] 个人档案 → 动作选择 → 摆机位 → 训练组 → 组后报告全链路。
- [ ] 会话恢复、历史、导出和用户删除。
- [ ] 获得授权的真人数据，覆盖体型、服装、设备、机位、标准/部分/不适配动作。
- [ ] 独立标注次数、阶段和应提醒事件，分别统计漏检、误提醒、提醒延迟和机位通过率。
- [ ] 收集使用者是否听懂、是否被打断、能否自行架好手机的反馈。

验收：与教练共同确定并冻结每项指标的发布门槛，独立留出集达标后才开放相应提醒；不以演示视频或合成测试替代准确性结论。

## 后续范围

俯卧撑与髋铰链、更多变式、iOS、可选同步和可选个性化建模。每个新动作单独验收。360° 采集不默认等于三维模型，更不能直接证明关节受力或动作安全性。
