# 第一版实时契约

`LiveCounter` 是单组、单动作、串行调用的纯 Java 状态机。`RULE_VERSION=live-candidate-1`；仅支持已显式选择的深蹲/站姿弯举候选，不执行动作分类。

观测包含单调毫秒时间戳、追踪 epoch、可空的二维屈曲角和拒绝原因。Android 适配器将 CameraX 首帧时间戳锚定到 `uptimeMillis`，保留后续相机时间差；不同相机会话不共享此锚点。MediaPipe 在单工作线程用 VIDEO 接口顺序处理相机帧，CameraX KEEP_ONLY_LATEST 丢弃待处理旧帧，无未来帧输入或离线标签回填。

姿态归一化坐标按实际旋转后图像宽高转为像素；置信度采用 visibility 与 presence 的较小值，阈值 0.6，缺失置信度按不可用处理。COCO17 命名映射、全身可见性、主信号和动作姿态门槛分别校验。前置镜像仅影响显示，不交换解剖学左右。分析画面与骨骼同帧，预览刷新率受推理速度影响。

从稳定伸展（屈曲角 ≤25° 持续 300ms）准备，超过 25° 开始候选；屈曲 ≥65° 持续 120ms 后，回到 ≤25° 持续 200ms 才形成一次完整候选，周期至少 600ms、最多 20s。上述研究参数尚未通过真人校准。

观测间隔 >350ms、非递增时间戳、追踪 epoch 变化、关键点缺失或姿态不适配都会清空未完成候选，保留本组已记录候选数。收到结果时超过 350ms 的帧不用于计数；600ms 没有结果时清空预览和候选。暂停、切到后台、音频焦点丢失都停止语音，恢复前重新准备。不自动续计进程退出前的半次动作。

追踪 epoch 使用人数变化和所选侧髋部位置突变进行保守中断；它不是身份识别，不能证明所有换人或机位移动都被检测。侧面判断是图像平面启发式，另需用户确认机位。MediaPipe 最大输出 2 人用于发现部分多人情况，不承诺完整多人检测；第一版限单人固定侧面实验。

反馈仅为报数，不输出动作合格或医学判断。每个候选记录规则版本、证据起止时间和 1500ms 后的过期时间，报数冷却 2s、无积压队列，缺少离线中文声音时只显示文字。实际 TTS 开始回调记录 `spokenAtUptimeMs`，未播报保持 null；它不代表耳机端声音真正到达的测量时间。

本地摘要 schemaVersion=1，包含会话 UUID、动作、身体侧、相机、开始 UTC 时间、持续时间、候选事件和模型指纹。持续时间为本组经过时间（包含暂停），不是有效运动时长。没有有效观测时 `candidateCount=null`、`countStatus=not_eligible_no_observations`，界面显示“—”；已有有效观测但未形成候选才可记录 0。uptime 字段只在当前进程/启动时间域内比较；不能当 UTC 或跨重启直接相减。最多保留最近 50 组，导出 JSON、删除历史均由用户操作，默认不存图像，无 INTERNET 权限。草稿标记中断，重启后可查看但不恢复半次动作。
